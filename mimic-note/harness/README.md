# AI 하네스 — 언제, 어떻게 AI 를 부를지 스스로 배우는 장치 (주인 구함)

> 상태: **틀만 있음 · 담당자를 기다리는 중.** 찾은 사람이 맡아서 완성합니다. 관련 GitHub 이슈의 "AI 하네스" 항목을 확인하세요.

## 왜 필요한가

패시브 스킬 [자동 다운로드]는 **규칙으로 시작**합니다(`passive/rules.mjs`, 빠르고 비용 0원). 규칙만으로 애매한 경우에는 AI(Claude)를 불러야 합니다. 그런데 **언제 부르고, 무엇을 넘기고, AI 답을 어떻게 쓸지**는 처음부터 정답이 없습니다. 그래서 판단 데이터를 모아 기준과 정확도를 점점 올리는 장치가 필요합니다.

## 지금 이미 모으고 있는 것

타이머가 돌 때마다 **그 컴퓨터(맥미니)에만** 한 줄씩 쌓입니다. 공개 저장소에는 올리지 않습니다.

`~/.mimic-note/harness/decisions.jsonl`

| 필드 | 뜻 |
| --- | --- |
| `at` | 실행 시각 |
| `rulesVersion` | 쓴 규칙 버전(`rules-v1`) |
| `fired` | 어떤 규칙이 발동했는지(E1 겹침, E2 이미 완료, T3 다음 단계 제안) |
| `escalations` | 규칙이 **AI 검토 후보**로 넘긴 경우(같은 일을 여러 명이 진행, 다음 단계 담당이 애매함) |
| `notified` | 누구에게 어떤 경로로 알렸는지 |
| `aiCalled` | AI 를 실제로 불렀는지(지금은 항상 false) |

## 맡은 사람이 할 일 (제안)

1. **정답 데이터 모으기** — AI 검토 후보마다 관리자가 실제로 어떻게 결정했는지(누구에게 맡겼는지, 무시했는지) 기록하는 방법 만들기
2. **호출 기준 정하기** — 어떤 후보에서 AI 를 부르면 관리자 결정과 잘 맞는지 측정(맞힌 비율, 비용)
3. **연결 방법 정하기** — AI 에 넘길 입력(작업 기록·미션·대전제)과 받을 출력 형식, 실패 시 규칙 결과로 되돌아가기
4. **점점 올리기** — 기준을 바꿀 때마다 같은 기록으로 다시 돌려 정확도가 올랐는지 비교(`rules.mjs` 는 순수 함수라 같은 입력으로 재실행 가능)

## 지켜야 할 것 (대전제)

- AI 는 제안만 한다. 배정·우선순위·보상 결정은 관리자가 한다(8조).
- 판단 기록에는 비밀값을 넣지 않고, 공개 저장소에 올리지 않는다(9조).
- AI 호출이 실패해도 규칙 결과로 계속 돌아가야 한다(패시브 스킬은 멈추지 않는다).
