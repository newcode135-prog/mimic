# 미믹노트 — 중앙 컴퓨터

팀원들의 미션·투두리스트를 관리하는 중앙 기록장입니다. 지금까지 정한 내용, 진행 과정, 체크인 방법을 모두 이곳에 모읍니다.
**초안(2026-11-13)** 상태이며, 미믹 클라우드 드라이브의 기존 코드·기획(`docs/`, `server/`, `web/`)과는 분리되어 있습니다.

> ⚠️ 이 저장소는 **공개(public)** 입니다. 텔레그램 토큰·chat id·비밀번호는 절대 파일에 넣지 말고 저장소 비밀값(Secrets)이나 각자 컴퓨터의 `.env` 에만 둡니다. 실제 업무 내용을 담기 전에 비공개 전환을 검토하세요.

## 0. 대전제

[`premise.md`](premise.md) — 이 게임·노트·회사 시스템의 규칙. 접속하면 **가장 먼저** 출력되고, 모든 플레이어·관리자·AI 가 그 세션 동안 따릅니다. 미션은 대전제를 바탕으로 주어집니다. 대전제는 대표관리자(창민)만 고칩니다.

## 1. 접속(로그인) 규칙 — 암호구 `이름 + 저장소 링크`

팀원이 Claude Code 에 정해진 암호구를 보냅니다. 이름은 한글 이름 또는 영문 아이디(대괄호로 감싸도 됨).

```
창민 https://github.com/newcode135-prog/mimic
lucas https://github.com/newcode135-prog/mimic
```

Claude Code 가 하는 일(저장소 `README.md` 맨 위와 `CLAUDE.md` 에 같은 지시가 있음):

1. 저장소가 없으면 `git clone`, 있으면 `git pull`
2. `node mimic-note/checkin.mjs 민호` 실행
3. **① 대전제**를 먼저 보여 주고, **② 미션 데이터베이스**에서 그 팀원의 남은 미션을 꺼내 Claude Code 가 화면에서 바로 전달 (지금은 텔레그램 없이)

Claude Code 가 전달하는 문구(예):

```
민호님의 미션 1번은 텔레그램 봇 만들기
   텔레그램에서 @BotFather 를 열고 /newbot 으로 봇을 만든 뒤 토큰을 받아요. …
민호님의 미션 2번은 봇에게 /start 보내기
민호님의 미션 3번은 토큰·chat id 전달하고 비밀값 등록
```

Claude Code 를 거치지 않고 직접 실행해도 됩니다.

```bash
node mimic-note/checkin.mjs 민호              # 남은 미션 보기
node mimic-note/checkin.mjs 민호 --telegram   # + 텔레그램 발송(봇 설정이 끝난 뒤)
```

## 2. 미션 데이터베이스

모든 미션은 [`data/missions.json`](data/missions.json) 한 곳에 모입니다. 화면의 1번·2번·3번은 **그 사람의 남은 미션 순서**이고, 미션마다 고유 ID(`M-0001`)가 붙습니다.

| 필드 | 뜻 |
| --- | --- |
| `id` | 고유 번호 `M-0001` |
| `assignee` | 담당 팀원 아이디 |
| `order` | 담당자 안에서의 순서 |
| `title` · `detail` | 미션 제목 · 설명 |
| `status` | `todo` · `done` |
| `createdBy` · `createdAt` · `doneAt` | 누가·언제 만들었고 언제 끝냈는지 |

```bash
node mimic-note/mission.mjs list                                   # 전체 남은 미션
node mimic-note/mission.mjs list 민호                              # 민호님 미션
node mimic-note/mission.mjs add 민호 "제목" "설명" --by 창민        # 미션 추가(관리자만)
node mimic-note/mission.mjs done 민호 1                            # 민호님 미션 1번 완료(M-0001 도 가능)
```

- 미션은 **관리자(창민·민호)만** 만들 수 있고, 완료는 **본인 미션만** 할 수 있습니다.
- 바꾼 뒤 **git commit·push** 해야 중앙(미믹노트)에 반영되어 다른 팀원과 Claude Code 가 봅니다.
- 다음 단계: 여러 명이 동시에 고칠 때의 충돌 처리, 오래된 완료 미션 압축·소거.

### 텔레그램이 보내지는 경로 (`--telegram` 일 때)

```
[팀원 컴퓨터의 Claude Code]
   └─ node mimic-note/checkin.mjs 민호
        ├─ ① 이 컴퓨터에 봇 토큰 + chat id 가 있음 → 바로 발송
        └─ ② 없음 → gh 로 GitHub Actions "미믹노트 체크인" 실행
                       └─ 저장소 비밀값의 토큰으로 발송 (토큰이 팀원 컴퓨터에 갈 필요 없음)
```

②를 쓰려면 팀원이 이 저장소의 **쓰기 권한(Collaborator)** 을 갖고 그 컴퓨터에서 `gh auth login` 을 마쳐야 합니다.

### 텔레그램 설정 (대표관리자가 한 번)

1. 텔레그램 **@BotFather** → `/newbot` → 봇 토큰 받기
2. 민호님이 그 봇을 열고 **/start** 누르기 (봇은 먼저 말을 건 사람에게만 보낼 수 있음)
3. chat id 확인: `TELEGRAM_BOT_TOKEN=<토큰> node mimic-note/checkin.mjs --chat-ids`
4. GitHub → Settings → Secrets and variables → Actions 에 등록
   - `TELEGRAM_BOT_TOKEN` = 봇 토큰
   - `TELEGRAM_CHAT_IDS` = `{"minho":"<민호 chat id>"}` (팀원이 늘면 여기에 추가)
5. 시험: `gh workflow run mimic-checkin.yml -R newcode135-prog/mimic -f member=minho`

## 2-1. 작업 기록과 패시브 스킬 [자동 다운로드]

```
플레이어마다 "자기 칸"에만 기록 ── data/players/<아이디>/work.json
  node mimic-note/work.mjs 루카스 라벨링 강의-001 시작
  node mimic-note/work.mjs 루카스 라벨링 강의-001 완료
        ▼  commit·push
⏱ 패시브 스킬 [자동 다운로드] (맥미니, 10분마다) ── passive/auto-download.mjs
  ① git pull 로 모두의 최종 기록 받기
  ② 규칙(passive/rules.mjs)으로 계산 → data/auto/todos.json (이 파일은 타이머만 씀)
  ③ 바뀐 사람에게만 알림
        ▼
🎮 1번 게임기: Claude Code — 암호구로 접속하면 ①대전제 ②미션 ③자동 투두
📱 2번 게임기: 텔레그램 / 맥 알림창 — "투두가 바뀌었어요" · "⚡ 더 중요한 일이 생겼어요"
```

**규칙 v1** (`passive/rules.mjs`)

| 규칙 | 언제 | 결과 |
| --- | --- | --- |
| E1 | 같은 대상·같은 단계를 2명 이상이 진행 중 | ⚡ 더 중요한 일(둘 다) + AI 검토 후보 |
| E2 | 이미 누가 끝낸 일을 다른 사람이 진행 중 | ⚡ 더 중요한 일 |
| T1 | 관리자가 배정한 미션 | 투두 맨 앞 |
| T2 | 내가 진행 중인 작업 | 이어서 하기 |
| T3 | 한 단계(라벨링→압축→업로드)가 끝났는데 다음 단계를 아무도 시작 안 함 | 앞 단계를 끝낸 사람에게 다음 단계 제안 |

- 알림은 **내 투두가 바뀌었을 때**와 **더 중요한 일이 생겼을 때**만 갑니다. 같은 내용은 반복해서 보내지 않습니다.
- 앞 회차가 안 끝났으면 이번 회차는 건너뜁니다(중복 실행 방지). 한 사람의 기록 파일이 깨져도 전체는 계속 돕니다.
- 맥미니 설치: `bash mimic-note/passive/install-macmini.sh` · 상태: `… --status` · 제거: `… --remove`
- 텔레그램: 맥미니 저장소 폴더의 `.env` 에 `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_IDS` (git 에 안 올라감)
- 규칙이 애매한 경우는 AI 검토 후보로 기록만 합니다. 언제·어떻게 AI 를 부를지는 [AI 하네스](harness/README.md)가 정할 몫(주인 구함).

## 2-2. [사고력 게임]

플레이어와 AI 가 `[ ]` 언어로 겨루는 게임. 각자 자기 칸(`data/players/<아이디>/games.json`)에 저장되고, 접속하면 **④ 마지막 사고력 게임**이 바로 보입니다.

- 출제자의 답은 **봉인**: `답 + 소금`의 sha256 만 공개 → 상대가 답한 뒤 공개하면 누구나 대조할 수 있음(답을 나중에 바꾸지 못함)
- `node mimic-note/game.mjs <이름>` 보기 · `answer "<답>"` 답하기 · `reveal "<답>" <소금>` 공개 · `judge player|claude|draw` 판정

**게임 규칙 v2** (대표관리자 창민, 2026-11-13 — G-001 이후 적용)

1. **목적** — 능력 증명이 아니다. **서로에게 지금 가장 필요한 것을 묻는 시스템**이다.
2. **숨은 의도** — 질문으로 상대의 yes/no 프레임을 확인한다. 답이 no 라면, 그 틀 밖에서 **모두가 만족하는 세 번째 제안**을 낸다([더블 바인드], [우문현답]).
   예: *Sometimes you win, sometimes you learn.* — 나에게만 이득인 답을 넘어 **서로 다 이득**인 답.
3. **문제의 형태** — 그 주제를 **가장 빠르게 실행 모델(MVP)까지** 만들 길을 찾는 질문이어야 한다.
4. **답의 형태** — 본질을 이해했음을 **[꿰뚫었다 [꿰]]** 형태로 보인다(본질을 꿰고, 바로 실행으로 꿴다).
5. **승리 조건** — 상대에 대한 **완벽한 인정**. 서로 인정하면 둘 다 이긴다. 인정이 안 되면 진 게 아니라 배운 것(learn)으로 기록한다.

## 4. 초월 시스템 — 지금까지 정한 방향

- 미믹노트는 사람들의 미션을 관리하는 **중앙 컴퓨터**입니다.
- 플레이어(팀원)는 각자 아이디가 있고, **그 아이디의 최종 투두리스트 + 모두가 함께 수행 중인 공통 미션**을 바탕으로 투두가 갱신됩니다.
- 갱신 주기: **10분에 1번** (패시브 스킬)
- 텔레그램 메시지는 각자의 최종 투두리스트에 따라 다르게 갑니다. 액티브 스킬 예: `[상태창]` → 레벨·퀘스트 창
- 투두를 수행하면 **보상**을 줍니다 — 이것이 초월의 핵심. 레벨 규칙은 나중에 천천히 추가.
- 데이터는 여러 명이 동시에 올려도 쌓이지 않게 **압축·소거** 합니다.
- 인원: 10명 이내로 시작 (지금 5명)
- 상세 개발 지시서: [`guides/초월-가이드-1번.md`](guides/초월-가이드-1번.md) (MIMIC TASK 가이드)
